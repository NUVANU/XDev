# R4 一次后继：单一规范授权域的受限试点

本说明承接 `FAILURE_SUCCESSOR_REQUIRED`，只支持当前明确授权的受监督试点：一个已结束失败前驱、一个准确 head、一个当前候选、一个冻结准入包和一个控制根，至多一次获准启动尝试、一次新 QA。旧失败、旧 start/claim 和消费保留，不退款、不在原终态 Job 改成成功。不提供共享余额池、自动续轮或新的调度/事务/记忆系统。

## 谁核什么

| 性质 | 实际边界 |
| --- | --- |
| 前驱失败已结束、写者/QA/副作用无未知，新依据与范围有效 | Host 根据原公开 final、失败回执和准确 head 核对；UNKNOWN 先原身份对账，不能以换 Job/Agent/授权绕行 |
| 冻结包绑定准确 request、当前候选、前驱/head/新依据及唯一规范授权源 | Host 准入责任；普通 `start` 不读取这个包或认证前驱语义，不能宣称 Core 有跨 Job 前驱锁 |
| 同一控制域和同一个规范授权来源 FileRef 只能占用一次 | 原 Core `consumeStart`：key 是整个 `{path,sha256}` 的规范摘要，`wx` 独占创建并持久化，先于 `createJob` |
| 槽与原请求、项目的绑定 | 原消费记录保留授权源、request path/hash、项目/root；已持久化合同重开时核这些原绑定，不能迁移或换源修复 |
| 新 Job 的正式交付 | 当前候选、本轮真实实施/采用结论、非作者 Review、实际 QA 原回执和 QA 本人 final，仍由同一既有 Core 判定 |

相同字节复制到另一文件路径，是另一个 FileRef 和潜在槽，不是同一个规范来源。不得用复制文件、换 request_id、换控制根或新增授权源充当旧槽重试。Core 只强制本控制域内已经选择的来源；它不阻止不受该冻结流程约束的其他独立授权。因此本试点证明 at-most-one 获准启动尝试，不承诺跨对象 exactly-once 成功或总能找回 Job ID。

## 冻结与进入

协调者先核原失败、准确 head、当前候选/新依据、范围、独立检查和当次许可。前驱不明、仍有活跃写者、仅 claim、外部效果或已占用槽的结果不明时，停止依赖路径，只读对账。

先固定规格、当前完整候选清单及授权条款。唯一规范授权源引用这些无环依据和前驱失败/head；request 再引用该准确来源；最后生成本次包，绑定全部 FileRefs，避免授权源与 request 摘要互相引用。包是已有公开任务/交接材料，不是第二份后继账本，也不向严格 request schema 塞新字段。

进入时用现有 `PreparationJson.psm1` 的 pin/根域读取原件，核当前候选与冻结清单及 scope，再走已经批准的 prepare/preflight/普通 start 路径。任何包/request/source/candidate 漂移都拒绝本次 Host 准入，不能临时更新包、借较早形状拒绝冒充槽竞争结果，或用参数自述授予额度。public-session-1 固定材料生成未覆盖用途仍是 UNSUPPORTED；不得伪造 A/B 工具通过或另造同类校验器自证。

## 故障后的实际含义

| 边界 | 保留事实与合法下一步 |
| --- | --- |
| 请求/窗口等在占用前明确拒绝 | 不产生新槽/Job。只依据当次有限纠正来源更正具体输入；NOT_STARTED_BY_THIS_CALL 不证明别处从未提交 |
| 占用持久化后、createJob 前失败/中断 | 槽保持占用；后续同源返回 AUTHORIZATION_ALREADY_CONSUMED。没有成功 Job 也不释放、不删槽或修复 partial bytes |
| createJob 已发生、合同证据或关联/回复未完成 | 可能已有 CREATE journal，但 Core 在 createJob 返回后才持久化完整合同。槽没有 Job ID 映射；孤立 journal 或相似目录不证明正确操作关联。取不到可核原对象时保持 UNKNOWN/受阻，不补合同、迁移、换 ID 或换源再 start |
| 完整创建后只丢外部回复 | 能从原返回/公开原件确定准确 Job 时，用原 ID 只读 status/result，核同一槽/request/合同与 journal。普通重复 start 仍是已消费拒绝，不保证返回原 Job ID |
| 两个不同有效请求争同一个准确来源 | 既有独占槽至多一个进入 createJob；其余明确已消费。不能把某个请求的更早 spec/shape/版本错误计为成功的竞争门禁 |

只读对账和一个新执行是不同动作。所有部分提交、原错误、超时、未知、额度与日志保持；不把 memory、作者摘要或未找到对象当成结束证明。新 Job 完成也不追认原失败当时成功。

## 明确未支持的自动路径

多授权来源竞争同一旧余额、动态追加/复用多 Job 可变额度、跨控制根竞争和自动改派均为 UNSUPPORTED，不进入本试点自动分配路径。即便不同来源各自能创建一个独立 Job，也不构成共享池正确性证明。

独立检查分别记两列：Core 反例核实际槽、创建数、精确拒绝、原件及查询副作用；Host 场景核包/request/candidate 漂移、多源/跨域/旧余额、未知前驱或无新依据时的拒绝/停止及实际调用为零。后者是明确的宿主政策判断，不标成代码硬拒绝。TEST_ONLY 回归只覆盖其合成输入，真实后继还须当前真实角色与一次实际 runner QA；安装、加载、实际采用及成本结论另验。
