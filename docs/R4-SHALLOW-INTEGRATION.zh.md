# Codex 浅接入与按缺口补位

Codex默认负责搜索、必要设计、编辑、调试、命令、会话和角色协调。XDev只在三个节点核当前事实和自己控制的交付，不接管逐次工具调用。新正式Node任务使用无档位request-5及当前确认要求，见[统一合同](R4-UNIFIED-CONTRACT.zh.md)。不按Agent品牌推断能力，不生成三种新套餐。

1. 进入：复用当前明确目标、允许/禁止范围、关键行为和回归AC、检查独立性、有限许可及候选，使用原prepare/preflight/start。用户给意图，协调者整理来源和机器字段。普通搜索/编辑/Host测试留给Host，无逐文件审批或每次编辑新Job。
2. 关键变化或中断：规格/范围/关键AC/已经登记的候选变化时重核受影响绑定。未登记的授权范围内普通编辑不是新Job。原操作claim/结果未知先按同身份只读recovery/status对账，不能换Agent/Job/回执或新验证绕开。确定的新版本按原规则重绑，旧失败/消费不退款。
3. 交付：核同候选的非作者Review、实际QA原回执、AC覆盖和所有阻断。查询原run-status/run-result，原账本给有限结论；Owner愿意接收未审实现仍不能让它成为正式质量通过。

| 实际观察的缺口 | 最小动作 | 放行或停止 |
|---|---|---|
| 规格、范围、候选或关键AC缺失/矛盾 | 指出具体缺项，协调者补来源，实质歧义由Owner或已采用XMi澄清 | 未补齐停止依赖动作，不猜“低风险”减项 |
| Host没有可核命令/候选/原始输出 | 使用现有有界runner；Host/CI替代须先单独验证来源和AC34/40 | 原运行不可核为SOURCE_UNVERIFIED；runner也不可用则UNSUPPORTED并阻断 |
| 非作者检查者缺失，或Review/QA没覆盖关键AC | 由可核独立检查者核原要求和当前候选，补足缺口 | 无独立性/覆盖不交付；明确允许时沿原verifier分轮职责，不固定三人 |
| 已知Review/QA失败且问题可定位、当前许可有效 | 给Host原失败用例、预期/实际、证据、范围、复验方法；首试点至多一次纠正 | 新候选重绑重验。无进展/超范围/额度耗尽停止；有当次明确交接许可才交更强Agent或人工 |
| 仅claim/仍活跃写者/副作用或提交未知 | 原身份只读对账，保留UNKNOWN | 不能换品牌、任务名或新授权绕过原操作 |
| 到期、停止或没有交接许可 | 停止依赖执行，准确报告缺口 | 不自动续期、重派、另造授权源或重置claim |

“更有能力”由本次实际行为决定。补位可以发现错误，但修成合格候选还需要真实重验；两种效果分别统计。一次纠正是该试点冻结的最大次数，不是Core增加的自动修复预算引擎。人工监督下已知终态后若获得具体当前新许可，可按现有一次start域另准入后继；须在原合同/交接明确前驱、原失败/head、新依据/候选和许可。没有当前授权不克隆来源，不把多个来源当共享余额事务；自动一次后继仍按S3c单验。UNKNOWN不适用此路径。

当前首路径为已验证的Codex/Node及原runner，MCP保留精确Node24.19.0/24.20.0、单条冻结命令和90秒上限。其他Coding Agent必须先证明原候选/运行/独立检查来源。没有合格直接来源时可使用本机已验runner；没有合格通道即停止，不接受作者自造或旧运行换壳。当前无Host/CI回执导入端点，不能将一组自洽JSON/hash当原运行证明。

默认登记仍复用public-session-1的真实worker来源或public-session-2显式角色合同。request-5正式Node可在编码前通过冻结spec明确选择[Host原样采用外部实现](R4-EXTERNAL-IMPLEMENTATION.zh.md)：绑定初始输入、完整最终源、全部改动映射和当前候选，直接提交非native来源声明，无需额外Codex复制角色。非作者Reviewer本人核来源conformance，实际QA和原receipt不变；外部日志不伪装worker或QA。缺完成观察、源/候选不一致或未知写者保持拒绝。各宿主真实完整链分别验收，不把结构自洽或此入口本身称为跨Agent质量/成本通过。

XDev拦截其控制的登记、QA和正式交付结论。实际合并/发布的硬拦截以已接入并验收的Host/CI为准；未接入时明确“外部发布门禁未配置”，不声称阻止全部外部编辑/发布。不增系统权限、ACL或后台服务。

记录原公开操作、候选/规格、节点、补位触发、有限纠正/交接来源和结果；复用现有Job/交接与准备工具，不造第二状态库。治理G/F、实际合格交付Q、模型/工具/人工成本C分开。缺测为UNKNOWN，首例与故障注入只证明对应路径，不证明较弱Agent普遍达到Codex或B组质量。
