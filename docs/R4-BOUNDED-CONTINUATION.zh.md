# R4 有界持续推进（MECH-03）

本机制复用Host协调者、现有任务卡/公开交接、Job和质量入口，在已确认需求、范围和具体授权内持续完成最终验收。Codex 主统筹者可按[里程碑 Goal](CODEX-MILESTONE-GOAL.zh.md)请用户选择是否为当前里程碑启动宿主原生 Goal。

## 每次阶段结束后检查总目标

实现、独立Review、实际QA、有限修复或一个Job自然结束后，协调者核对：总目标和剩余AC、当前候选/规格、适用权限和剩余额度/期限、原角色/写者状态及依赖。存在已授权、前置齐备的下一步时直接接续，用进度消息说明进展，不因输出阶段报告而等待用户再说“继续”。同一Job的COMPLETE只是该Job登记完成；它不是总目标全部验收完成。规格或候选变化仍按原规则重绑，旧Review/QA不能换绑。

实现者和独立检查者按各自合同正常自然final、留下原回执并返回协调者。SubagentStop不要求已完成角色继续运行；协调者收到结果后负责下一阶段。持续推进不改变非作者Review、实际QA、不同职责/自然final、QA receipt及最终run-status/run-result要求，作者自测不能替代正式独立检查。验收后已有安装授权覆盖时，继续原安装/回退流程；安装、加载和实际采用分别留证。

## 正确消费现有状态

| 字段/结果 | 解释与下一动作 |
|---|---|
| `primary_next_step.status=ACTION_REQUIRED` | 根据action核当前具体授权和前置，由Host协调下一步。建议不是执行许可。 |
| `automatic_execution=false` | XDev运行时不会自动派发/执行建议动作。不能单凭它推出“Host必须等用户”。 |
| `execution_allowed=false` | 原查询中的当前Job聚合标记，不是整个Host工作流的继续开关。不能据此自动要求确认，也不能忽略实际动作的权限、版本、claim、时限和独立性门禁；具体入口仍自行校验。 |
| `delivery_allowed=false` | 尚不允许正式交付；Review、QA、合法修复或只读对账是否可做，取各自实际前置。 |
| `COMPLETE / COMPLETE_UNVERIFIED` | 完成范围仅当前Job；后者仍未正式验证。回到总目标检查，不把未验证输出变成绿色交付。 |
| `BLOCKED / UNKNOWN / UNSUPPORTED` | 保留原义，核reason/action与原证据。阻断重复执行/交付不等于必须等Owner；可能仍需等待原角色、原身份只读对账或推进已授权独立工作。没有合法路径才停止受影响范围。 |

`primary_next_step.interpretation`是静态只读解释：`coordination_owner=HOST`、`automatic_execution_scope=XDEV_RUNTIME_ONLY`、`completion_scope=CURRENT_JOB`、`permission_granted=false`。最后一项表示这个投影不授予任何权限，不是对既有授权的撤销或对下一动作的许可判断。元数据不作“用户是否必须输入”的决定，不执行工具，也不增加Core状态或改变现有布尔值。CLI与MCP共用该投影，MCP继续叠加真实本机权限；旧消费者仍保留原字段，不能只取一个false决定整个工作流。

## 阻塞只停止受影响路径

在既有任务/交接中记录具体原因、原输出/引用、受影响范围和依赖、解除条件、已试方法及累计消费/剩余额度，区分已确认事实与假设。正在提交的原子动作按原有界规则安全收尾。UNKNOWN、claim-only或活跃/未知写者先按原key/Job/版本只读对账，不重写未知提交、不换ID、删锁、重置claim或重跑原QA。

已有授权覆盖的明确暂挂/停止处置完成后，可按MECH-01单卡与依赖规则继续确实独立的工作；不能把依赖失败核心的部分拆成绿色交付。需Owner决定的产品需求/范围、新权限、副作用、付费额度或安全设置，列明具体选择及影响后等待；登录等必须人工处理的事项也明确说明。用户未回复不构成同意。缺证据而又无法合法补齐时，停止依赖该证据的路径。

## 有限尝试与停止出口

沿当前具体合同和有限余额执行；既有更严格的一次纠正、截止、取消或停止条件优先。处理同一问题时累计实际方法、结果、失败/STOP/UNKNOWN和消费，不因换角色、模型、目录、会话或Job清零。无新依据不重复尝试。同一阻塞连续两个事前获准且已结束的处理回合仍未收敛时，停止第三次同路修补，重评根因和最小路线；重评不自动产生新修正、测试、角色、额度或期限。

确定失败后的新Job仍须满足现有受限后继入口及当次具体许可。XDev 运行时的自动续轮和共享预算仍UNSUPPORTED。不要为了保持运行扩充无关功能、验证工具或审核平台。所有已授权可行工作都完成最终验收，或仅剩确需用户处理/决定、硬限制或无合法路径的事项时，协调者才以完整结果和未完成范围结束；不要把阶段报告充当这个出口。

## Host能力边界与验证

Stop Hook只提醒协调者检查总目标，SubagentStop提醒保留角色自然final。它们仅返回systemMessage，不阻止结束、不发起执行。用户已启动的 Goal 由 Codex 管理，接续能力取决于宿主生命周期。XMem只保留获准公开接续资料，不授予权限或执行目标。

纯投影测试验证状态/action/旧布尔值、权限拒绝、UNKNOWN、终态和解释元数据；Hook测试验证非强制响应及角色区分。真实宿主验收另记录一次授权后的实际阶段接续、总目标检查、局部阻塞处置和有限停止；fixture或文字存在不能替代真实行为，未跑项标NOT_RUN。独立Review、实际QA、安装、加载、后续采用分别报告，不据此声称所有宿主或跨idle能力通过。
