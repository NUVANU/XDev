# R4 操作类型与风险（MECH-02）

先判断请求是否改变产品行为/协议，再结合副作用、可回退性和实际授权选择流程。这是Host/协调者的技能政策，不新增Core状态、request字段、权限、代码分流器或强制沙箱。

| 类型 | 判断与默认行为 |
|---|---|
| 日常操作 | 已有能力支持、范围清楚且可回退，如一般路径/配置、备份搬迁、普通文档修改。直接完成必要检查和备份，执行后核结果；不默认生成产品卡/Job、MCP项目绑定、独立Review或产品QA。 |
| 高风险叠加 | 唯一数据副本、不可逆变化、共享生产/多项目影响、安全或凭证策略。具体核影响、恢复方案和授权；按风险或Owner要求增加独立复核。已有授权内的准备直接做，只汇总真实缺失的决定/权限，不逐文件询问。 |
| 产品开发 | 产品代码/行为/协议变化，新增可复用产品能力，或自行实现新的转换/并发恢复语义。按当前开发合同完成范围/版本绑定、非作者独立Review和实际QA。作者自测不能替代正式独立检查。 |

高风险可叠加于另外两类。不能按文件扩展名、代码行数或“小脚本”降级；一次性脚本若只是编排既有能力，也不因此自动升级。既有Job和已承诺的Review/QA继续按原合同完成，不能重新贴“日常操作”绕过已有门禁。产品开发仍遵守MECH-01单卡/依赖/滚动交付及原runner、claim、有限授权、失败规则。

## 默认尺度

- 先复用已支持的工具。UNSUPPORTED先定位具体缺口，查已有公开CLI/SDK或正常操作能否完成；只有确需新增产品能力且适用开发授权覆盖时才进入开发，不自动“补工具→审工具→再操作”。支持的准备材料仍走已有公开入口，不另写同类校验器。
- 一般操作在已有交接中简记目标、范围、回退和结果即可；原合同/具体风险需要的原始回执照留，不默认增加多套状态、完整产品清单或A/B材料。不为常规可逆实施细节重复索取已给授权。
- 检查对应实际风险：数据迁移核一致快照、内容/附件、配置位置及旧记录/新写读回；普通说明核实际改动；产品开发按当前合同实际Review/QA。具体风险或Owner明确要求的额外检查仍执行。
- UNKNOWN、断连或疑似部分提交先按原身份只读对账，保留失败和消费；不能换key/Job重来、删锁或以“操作简单”猜成功。明确失败才按适用的有限纠正规则处理。
- 新库/新配置已接收写入时，直接切旧副本可能丢数据；先核新旧状态和差异，再决定回退或修复，不自动回滚未知副作用。
- 原生XMem按已配置项目与实际授权使用，任务级开始/查询、关键公开发现和阶段checkpoint遵守现有规则并复用已核材料；不为每条命令捕获记忆、不把XMem变成未配置项目的新前置。记忆不提供授权，也不替代Review/QA。本政策不要求修改XMem核心/协议或启用旧bridge。

## 两个示例

用户已授权把项目缓存迁到另一个目录并保留旧副本：先核现有备份/迁移能力，完成一致复制、配置切换和真实读取核验。一份简短操作记录足够，不默认造开发卡、派产品Review/QA。存在唯一副本或共享服务影响时，针对该具体风险补恢复安排与缺失授权。

用户要求给产品新增批量查询，或修复正常输入被错误拒绝：这是产品开发，即使只改一行也要绑定当前需求/候选，完成非作者Review和实际QA。同一开发卡继续原阶段，不能用普通配置/脚本标签豁免检查。

## 结果与采用

日常操作以真实结果和必要核验收尾，不冒称产品VERIFIED；高风险复核说明具体风险和实际结论；产品质量取原Review/QA与当前版本结果。未知仍UNKNOWN。

技能政策改动选择相称的非作者Review和独立宿主场景验证，不因改规则重跑未变化的整套Core/SDK。静态文本存在不算行为通过。验收、安装、当前会话重读、fresh加载和后续真实采用分别记录，不把模拟场景或安装成功当成全部宿主/长期收益证明。
