# R4 真实新增与修复的最小交付路径

对已选定的实际项目，先依据当前需求和仓库规范确定小范围变更。Owner明确委托选题或技术细节时，协调者可整理成最小合同，并如实注明委托依据；不把协调者选择说成Owner逐项审阅，也不要求用户手填机器字段。实质歧义仍回到公开讨论，必要时再使用已采用的XMi。

新增与修复分别明确触发、目标行为、错误边界、应保留行为和实际入口。新增不虚构旧Bug。修复先在原候选复现真实缺陷，保留原始输出；环境拒绝、采集失败或退出码不可测要单列，不能当成功的RED。只改必要实现，冻结独立验收用例和原回归。

普通正式Node任务沿用request-5的无档位合同、确切project/spec/scope/manifest、有限授权、非作者Review与实际QA。进入时准备/核绑定，宿主负责正常实现和调试；关键变化或中断重核受影响依据；交付时通过原Core核同一候选/Job的完整证据。各自独立完成新增和修复Job；若下一变更会使旧Job候选漂移，先保留可复验的原候选和原结果。不同副本/项目身份必须显式绑定，不能把新结果写进旧Job。

从原start返回实际Job和Host动作，使用真实公开角色来源。实现结束后登记原作者自然final。独立Reviewer比较原意图、当前规格、最小设计及真实差异，逐项给出checks和scope/preparation结论。QA由合同允许的非作者角色本人通过现有有界runner执行冻结命令，亲自检查完整原始输出及原receipt，再自然结束；协调者随后登记同一原final和receipt。最后查询run-status与run-result，不能用作者自测、工具CHECKED或单条成功命令替代交付判断。

当前public-session-1是协调者转交公开工具来源，不认证原生身份。现有完成载体保留task_name、status=completed、stop_requested=false和完整原final字符串；Review/QA还按原协议投影该原final的decision/checks及相应scope/qa结论字段，QA保留其本人准确receipt。投影只复制原角色已经实际作出的结论，原件、调用和失败输出均保留；不得补签或从PASS文案推断缺失boolean。固定材料工具不支持该载体或FORMAL_QA_SUBJECT时明确UNSUPPORTED，沿既有Core协议登记，不能伪称准备工具已检查。

实际入口按当前承诺验证：纯模块用真实导入调用，CLI用真实命令，HTTP/UI只有涉及或承诺时才另验。测试中的真实副作用、临时文件和数据输出必须留在批准隔离域，QA前后核候选及输入守卫。原业务目录保全、隔离副本可运行、原地升级、安装和fresh加载分别记录。数据/配置会影响行为时显式纳入边界，不能用无说明的复制过滤或ignore隐藏输入。

仅在同版本独立检查、实际QA与本次AC成立后记录已验收，再按现有授权准备独立交付和回退、实装及目标Host加载验证。下一条真实任务实际使用该版本才记录采用。只写过程说明或生成材料不记实装；旧版本、失败、期限、消费与UNKNOWN保留。原final回放及一次后继仍适用各自已有规程与明确支持范围，本节不扩展恢复、调度、共享预算或外部发布权限。

支持边界继续是当前已验Codex公开角色来源和Node24.19.0/24.20.0的既有runner。无额外数据库、后台hook、调度器或逐文件审批；外部Host/CI回执、浏览器、外部发送、远端发布及更大仓库能力分别验收。真实应用局部通过不证明跨Agent质量等价或节约成本。
