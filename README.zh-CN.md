# XDev

**让“开发完成”有据可查。**

面向 AI 辅助开发的轻量工程治理层：沿用宿主的开发能力，补上范围检查、交付判断与有界恢复。

[English](https://github.com/NUVANU/XDev/blob/main/README.md) · **简体中文**

[开始使用](https://github.com/NUVANU/X-Suite/blob/main/INSTALL.md) · [社区工作流](docs/COMMUNITY.md) · [X Suite](https://github.com/NUVANU/X-Suite)

AI 说功能已经完成，但它做的是你确认的需求吗？Review 看的是这份代码吗？QA 真的运行了吗？对话中断后，是否已有结果可以恢复，还是又执行了一遍？

**XDev 将交付结论与实际项目、候选代码和验证证据关联起来。** 搜索、设计、编码、调试和 Agent 协调继续交给宿主；XDev 重点检查任务进入、关键变化或中断、最终交付三个节点。

## 它能解决什么问题？

| AI 开发中的常见问题 | XDev 提供的检查 |
| --- | --- |
| 文件同名，却属于另一个项目或旧版规格 | 显式绑定项目、来源、版本与文件内容 |
| “顺手优化”变成未经确认的新功能 | 保留批准范围，并在 Review 中检查符合性 |
| 作者自测被写成“独立 QA 已通过” | 区分实现、非作者 Review 与实际 QA 证据 |
| 审查、测试和交付对应不同代码 | 将阶段记录绑定到同一候选和任务 |
| 中断后重复运行、丢失失败记录 | 先只读诊断和对账，再按权限有界恢复 |
| 普通文件操作也走完整开发流程 | 按操作类型与具体风险选择必要检查 |

适合持续维护的产品、多会话开发与 Agent 交接，让用户有依据判断交付状态。

## 0.1.6 更新了什么？

**用 Codex 原生 Goal 接续已批准的里程碑。** 主统筹会话可就当前已确认的开发里程碑，提供一次启动 Goal 的选择。创建前核对已有 Goal、项目、XSpec 版本、验收项与授权；已有未完成 Goal 时保留原目标，选择“稍后”或未回复都不会创建。

Goal 是可选的宿主能力。能力缺失或用户暂不启用时，正常授权工作继续；范围、预算、非作者 Review 与实际 QA 仍然适用。本次保留 0.1.5 已有的项目内数据布局。

详见[更新与验证范围](docs/PUBLIC-UPDATE-20261125.md)和[里程碑 Goal 流程](docs/CODEX-MILESTONE-GOAL.zh.md)。

## 0.1.5 更新内容

本次为普通受监督任务增加显式的项目内数据布局。

- **将受支持的任务数据放在项目内。** 可选择工程直属 `.xdev`，其中固定为 `control/`、`input/` 和 `local-config.json`；安装仍先保持 UNBOUND，已有目录不覆盖、不自动迁移。
- **只排除保留的数据路径。** 本布局的候选清单排除上述三个路径，`.xdev` 内其他产品文件仍正常纳入。输入范围、物理目录身份、链接、别名与其他重叠检查继续执行。
- **高级工作流继续用外置布局。** XSpec 接收、旧 XMem bridge 与外部实施产物采用仍需外置数据根；原生 XMem 连接独立配置。

选择前请阅读[项目内配置与限制](docs/LOCAL-MCP.zh.md)。

### 有界持续推进继续保留

已有接续规则沿用宿主工作流与当前授权。

- **阶段结束后继续检查总目标。** 还有已授权、前置齐备的下一步时直接接续，不再要求用户重复说“继续”；各角色仍提交自己的自然 final 与原始回执。
- **正确理解当前 Job 状态。** 单个 Job 完成不等于总目标完成；运行时自动执行标记只描述 XDev 自身，既不撤销已有授权，也不产生新权限。
- **阻塞与尝试有边界。** 保留原证据、依赖、累计尝试与消费；UNKNOWN 按原身份对账，停止受影响路径，确实独立且已获授权的工作可按规则继续。原截止、停止与更严格的纠正规则优先。

详见[有界持续推进](docs/R4-BOUNDED-CONTINUATION.zh.md)。Stop hook 只作提醒，不承担调度或关闭会话后的后台唤醒。

### 保留的治理能力

- **新正式任务统一合同。** 普通正式 Node 任务采用无 profile 的 v5 请求，不再让新任务选择三档。旧 v1—v4 协议和既有 Job 保留原义。
- **默认浅接入。** 让宿主自主开发，在进入、关键变化或中断、交付时核验，不逐文件制造审批。
- **日常操作分流。** 已有能力支持、范围清楚、可回退的操作，不默认创建产品 Job、绑定 MCP 或派产品 Review/QA；产品行为、协议变化继续保留独立检查。高风险按具体影响叠加核验。
- **恢复有边界。** 区分 QA 未运行、声明待对账、原结果可恢复与需要新验证；保留 UNKNOWN、失败和已消费次数。
- **复用已配置的原生 XMem。** 按实际项目与任务检索历史，关键公开发现保存后完整读回；未配置时不把记忆变成新前置，也不从历史获得授权。

上述分流属于**宿主与技能政策**，不代表新增了 OS 沙箱、跨任务代码锁或自动调度器。详见[操作分流](docs/R4-OPERATION-ROUTING.zh.md)和[浅接入](docs/R4-SHALLOW-INTEGRATION.zh.md)。

## 开发流程

```text
确认目标与实际项目
        ↓
必要准备与预检
        ↓
宿主实现 → 非作者 Review → 实际 QA
        ↓
绑定当前候选的结果与交付判断
```

新正式任务使用[统一合同](docs/R4-UNIFIED-CONTRACT.zh.md)。协调者从已确认事实准备受支持的结构化输入，普通用户无需手写 UUID 或 JSON。解析成功、回执存在或 READY 状态本身不授予开发权限。

发生中断时，先检查原 Job、版本、执行回执和最终结论。只有满足当前授权和支持路径，才能恢复同候选的原结果；不能删锁、退款或换名新建 Job 绕过未知结果。详见[QA 恢复](docs/QA-RECOVERY.zh.md)。

## 快速开始

**公开源码：0.1.6 · MPL-2.0 · 本机验证路径为 Windows/Codex。** 来源与公开封装差异见[更新说明](docs/PUBLIC-UPDATE-20261125.md)。

文档使用 Node.js **24.20.0**、pnpm **11.25.0**、npm **11.19.0**：

```powershell
# 在干净的 XDev 源码目录中
pnpm.cmd install --frozen-lockfile --ignore-scripts
npm.cmd --prefix mcp ci --ignore-scripts
npm.cmd run typecheck

# 将内含 Skills 与未绑定项目的 MCP 入口安装到 Codex
codex plugin marketplace add . --json
codex plugin add xdev@xdev-community-local --json

# 输出当前源码目录的具体连接参数
node --experimental-strip-types mcp/configure.ts --host codex
```

保留源码目录。本地 marketplace 安装 Skills 和默认 MCP 入口；`configure.ts` 只输出手动或其他宿主接入参数，不自行注册。不要在插件之外重复注册第二份 XDev 服务。无项目参数的服务只暴露 **UNBOUND context**，不会擅自选择当前目录、创建 Job 或获得执行权限。

项目设置和原生 XMem 接入见 [X Suite 安装指南](https://github.com/NUVANU/X-Suite/blob/main/INSTALL.md)及[本地 MCP 指南](docs/LOCAL-MCP.zh.md)。安装、任务授权与宿主实际加载分别核验。

设置完成后，可以这样提出任务：

```text
请沿用宿主的正常开发能力，完成本次已确认任务。
在进入、关键变化或中断、交付时使用 XDev。
保留范围、候选代码、非作者 Review 与实际 QA 的对应关系。
使用已配置的 XMem 检索适用历史，保留未知与失败。
说明实际交付内容，以及仍缺少哪些证据。
```

## 技术设计

| 机制 | 作用 |
| --- | --- |
| 共用核心的 MCP、Skills 和源码 CLI | 提供结构化检查，沿用宿主执行能力 |
| 版本化合同、FileRef、哈希和候选清单 | 绑定实际项目、范围和文件字节 |
| 持久 Job、claim 与质量记录 | 区分实现、审查、执行和交付 |
| 受支持的 Node QA runner | 保存冻结命令的实际执行回执 |
| 只读诊断与幂等结果处理 | 先对账再决定下一步，减少重复执行 |
| PowerShell 准备工具 | 复用有界材料检查，减少重复造校验器 |
| 原生 XMem 与可选旧桥接 | 在明确项目和任务政策下检索工程证据 |

旧 XMem bridge 仍只接受指定的已核运行包与存储模式，**XMem 0.1.2 不会自动获得旧桥接资格**。本次更新优先使用宿主直接连接的原生 XMem，不应仅修改白名单来强行接入新包。

## 职责边界

- **宿主与模型：** 搜索、设计、编码、调试、调度、会话、权限与生命周期。
- **XDev：** 任务和范围绑定、交付判断、证据检查与有界恢复。
- **XMem：** 持久历史、修订、来源引用与检索。
- **XMi：** 按需澄清产品并形成用户确认的规格。

哈希证明内容一致性，不证明结论正确或真人身份。XDev 不拦截每一条 shell 命令，也不保证模型必然遵守所有规则。

## 验证范围与限制

0.1.6 公开集成通过类型检查、**35/35** 接续/钩子测试、**65/65** 配置/UNBOUND 测试及隔离 SDK/stdio 版本与绑定核验。Goal 增量另有非作者源码 Review 记录；这些检查不证明真实产品 Goal 创建、跨回合采用或当前会话热加载。详见[本次更新](docs/PUBLIC-UPDATE-20261125.md)。

布局改动通过非作者源码 Review，以及项目内、外置两种绑定的独立只读 stdio 核验。相关回归包 **65/65**、类型检查通过；合成批准 Job 的启动与查询不代表完整业务实现/Review/QA 闭环通过。测试卷无法执行的 Windows 大小写异名目录分支、历史集成失败与 UNKNOWN 均保留，详见[验证范围与限制](docs/PUBLIC-UPDATE-20261120.md)。

MCP QA runner 继续保留精确 Node **24.19.0 / 24.20.0**、一条冻结命令和**最长 90 秒**的边界。浏览器/UI、游戏引擎、其他宿主、无人值守、全新机器安装和长期收益需分别验证。本次源码同步不构成具体缺陷下降率或 token 节省比例的证明。
